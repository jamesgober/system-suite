# system-suite v0.9.5 - Lists and empty sections

**`.conf` files read empty sections and lists of tables, through config-lib 1.5.** No API change.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Added

- **Lists of tables.** A `.conf` file can hold `[[upstream]]` lists, read with TOML's rules: the keys after the header go into a new item, and a `[upstream.tls]` header after it belongs to the last item. The header used to fail on its first line. A list reaches the application through `Config::backend()`. A list item cannot hold a secret yet, neither a reference nor a plain value under a secret-marked key, since a secret is named by its path.

## Fixed

- **A section with no keys reaches the application.** `[auth.passwrd]` or `[content.fields.post.author]` with nothing under it vanished, so `Config::keys` of its parent never listed it: a misspelled empty section passed a key check, and an intentionally empty one was never seen. It is now an empty table, as in TOML. An empty sub-section of one of the suite's own sections (`[log.levle]`) is refused as an unknown key.

## Members

config-lib 1.5 is required (was 1.4). The others are unchanged from 0.9.4.
