# system-suite v0.1.0 - Scaffold

**The repository and the plan.** v0.1.0 set up the crate in the portfolio template and wrote down the design before any code. There is no functional code in this release; it also claimed the name on crates.io.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, and ids, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse. Each part is its own published library behind its own feature.

## What's in 0.1.0

- The crate manifest: edition 2024, MSRV 1.89, no dependencies, `Apache-2.0 OR MIT`, one feature per member declared ahead of its code.
- The crate root: `VERSION`, `unsafe_code` forbidden, missing docs and `unwrap`/`expect`/`panic` in library code denied.
- CI on Linux, macOS, and Windows, each on x86_64 and aarch64, on stable and 1.89; documentation built with default and all features; `cargo package`; `cargo audit` and `cargo deny`.
- `dev/PLAN.md`: purpose, scope, the members and what each still needs, requirements, the kernel, the boot and shutdown orders, the API outline, nine threats with their tests and costs, performance targets, the testing plan, open decisions, and the decision log.
- `dev/DIRECTIVES.md` (engineering law and definition of done) and `dev/ROADMAP.md` (phases 0.2 to 1.0 with exit criteria).

## What's next

`0.2.0` locks the public API in `docs/API.md`, writes the boot-order document, and settles the open decisions (where the kernel lives, the configuration backend, which members are on by default). `0.3.0` ships the first boot path: `start`, `run`, logging, paths, environment, signals, crash capture, and the kernel's shutdown order.
