# system-suite v0.9.2 - Checked opens

**Every file the suite trusts is opened through path-lib's checked open.** No API change.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Security

- The configuration, `.env`, `file:` secret, and audit-chain files are opened through path-lib 1.3's `open_checked` on every OS. The owner and permissions are read from the opened handle, so the file checked is the file read, and the open does not block: a FIFO swapped in after the regular-file check is refused instead of hanging the boot. The owner check no longer needs the `sys` feature.
- A system-wide `.env` file must not be readable by other accounts, since it can hold the values of `env:` secrets for a privileged service.

## Changed

- A refused file names what to fix: path-lib's reason, and a `chmod`/`chown` (Unix) or `icacls` (Windows) action.
- A file reached through a link is followed to the file it names, which is the file checked, so Kubernetes config-map and secret mounts keep working.
- A file on a Windows volume without access control lists (FAT, exFAT) is still accepted, so portable installs on such drives boot.
- env-lib 1.1 and clock-lib 1.2 are required.
