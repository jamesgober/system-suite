# system-suite v0.9.3 - Boot reports

**Two fixes from a macOS test of WASP's gateway.** No API change.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Fixed

- **The configuration step says what it did.** Its report ran before logging starts and was lost, so a working-directory file that was skipped, or a boot on the defaults, left no trace. It is now written with the first log lines: the file in use at info, with its path; at warn, a skipped `./<name>.conf` with the file and the reason (the process is elevated, or its elevation is unknown because the `sys` feature is off), and a boot on the defaults with the directory searched. The rule itself is unchanged: a process whose elevation is unknown does not read the working directory, so turn on `sys` or name the file with `<NAME>_CONFIG`.
- **The last log line names the right exit code.** A staged `Boot` dropped after a failed `start` logged `stopped exit_code=0` while the process exited 70, and so did a `System` or `Boot` dropped when `main` returned early. The line now names the failed start's code, or the stop's code after a stop request, and otherwise says the exit code is "set by the application".
