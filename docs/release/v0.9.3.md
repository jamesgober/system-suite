# system-suite v0.9.3 - Boot reports

**Two fixes from a macOS test of WASP's gateway.** No API change.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Fixed

- **The working-directory configuration file is read again without `sys`.** A build with `config` but not `sys` could not tell whether the process was elevated, so it skipped `./<name>.conf` without a word and booted on the defaults. The `config` feature now turns `sys` on, so the check runs: a process that is not elevated reads the file, and an elevated one still does not. If the OS refuses to report the elevation, the file is skipped with a warning in the first log lines.
- **The last log line of a failed staged boot names the right exit code.** A `Boot` dropped after a failed `start` logged `stopped exit_code=0` while the process exited 70. It now logs the failed start's code. After a stop request it is 0, and a `Boot` dropped before `ready` for the application's own reasons logs `exit_code` "set by the application".
