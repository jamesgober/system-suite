# system-suite v0.3.0 - First boot path

**A service boots with one call.** v0.3.0 shipped the first working path through the suite: `start!()` boots the members in the documented order, `run()` parks the thread with zero CPU until a stop signal, and the shutdown runs in reverse within a deadline. A failure anywhere in the boot unwinds what started and says what failed and what to do.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, and ids, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse. Each part is its own published library behind its own feature.

```rust
fn main() -> std::process::ExitCode {
    let system = match system_suite::start!() {
        Ok(system) => system,
        Err(error) => return error.report(),
    };
    system_suite::log::info!(system.log(), "ready");
    system.run()
}
```

## What's in 0.3.0

- **The boot order:** build info, instance, paths, environment, the process guard (single-instance lock, umask `0o027`, open-file limit), the signal intake, directories, logging, crash capture, the kernel, ready. Every step that can fail was made to fail in a test, with a real trigger, and left nothing running.
- **Signals:** SIGTERM, SIGINT, and SIGQUIT stop the process; SIGHUP and SIGUSR1 are received without stopping it; on Windows, Ctrl+C, Ctrl+Break, console close, logoff, and system shutdown stop it. A stop signal during boot is honoured at the next step boundary and the process exits 0.
- **Shutdown:** in reverse, within a deadline (25 s by default); a step that does not finish is abandoned and the exit code is 79.
- **Crash capture:** a panic is logged and flushed, and an owner-only crash report lands in the log directory with the build, the instance, the panic, and the last 64 log lines, already redacted by the logger.
- **Files other users cannot read:** the log and lock directories are owner-only on every OS (mode `0700` on Unix, a protected access control list on Windows), and the log files are `0600`.
- **Errors with exit codes:** one `Error` type naming the step, the member, and what to do; exit codes follow `sysexits.h` (75 for a second copy, 78 for a bad `.env` file, 73 for a directory that cannot be created, and so on).
- **systemd:** `READY=1` when ready and `STOPPING=1` when the shutdown starts.

Getting here took two member releases, made in the members themselves: path-lib 1.1.0 (owner-only directories on every OS) and log-io 2.1.0 (a ring of recent lines for crash reports, and file modes). sys-lib 0.3.0 provided the boot kit.
