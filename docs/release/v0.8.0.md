# system-suite v0.8.0 - Alpha

**The API is in the shape it should keep, ready for the first consumers.** v0.8.0 makes the breaking changes the review against a platform boot and database start-ups asked for, adds JSON on James's own jsonx-lib, and carries the first pre-1.0 pass over the suite and over the members released for it.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Breaking changes

- `UrgentLine::set` only raises the level. Lowering takes `UrgentLine::shift(from, to, reason)`, which moves the line only if it is at `from`, so a `Lockdown` cannot be undone by a stray `set(Normal)`; lifting one is audited.
- Urgent and stop reasons take owned text (`impl Into<Cow<'static, str>>`); a literal still costs nothing. Reasons are cut to 256 bytes.
- `Notice` is `#[non_exhaustive]`, no longer `Copy`, and carries the level it replaced.
- `Foundation::events()` returns a listen-only `Events` handle, so application code cannot publish a kernel event.
- A same-level `set` changes nothing, and a handler of an urgent change cannot change the line (it is refused).

## Added

- `config-json`: `<name>.json` configuration files through config-lib 1.2 on jsonx-lib. A repeated key is refused, the depth and size are budgeted, and the top level must be an object of sections.
- `metrics-json` and `metrics-otlp`: metrics-lib 2.1's JSON and OTLP exporters on jsonx-lib, without serde. A snapshot of 159 series is written in 26 us against serde_json's 39 to 40 us, with the same text.
- `Kernel::request_supervisor_stop`, `EventGuard`, and `EventId`.

## Fixed

- Urgent changes from several threads could be reported with the wrong level; each change, its epoch, and its reason are now one ordered step.
- The shutdown's own audit record is bounded by the deadline, and a reload in progress finishes before the subsystems stop.
- A flood of reload or dump signals runs one thread at a time, not one per signal.
- A backoff too long to add to the clock waits for the stop instead of restarting at once; a low memory mark clears; names ending in '.' are refused.
- An audit field holding the byte `0x1f` is recorded with U+FFFD in its place, so text from a request cannot keep its record out of the chain.
- Stopping with a timer armed takes about 0.2 ms instead of 1.3 to 2.0 ms.

## Members

- signal-mod 2.1.1: waker and payload panics contained, Windows service status sent in order, no escalation from OS events, the uninstall lock.
- audit-trail 1.2.0: unambiguous hashed fields, a bounded reader, one writer per file, no symbolic links, no writes after a torn record.
- config-lib 1.2.0 and metrics-lib 2.1.1: the JSON backends on jsonx-lib 0.5.1, which formats floats itself and writes the same bytes faster.

## What's next

0.8 stays open until a platform boot and a database start-up run on it on every listed environment, and the API is reviewed against that real use. The 1.0 readiness note (`dev/READINESS-1.0.md`) lists what is still open and why.
