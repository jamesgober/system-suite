# system-suite v0.5.0 - Feature complete

**Every member is wired.** v0.5.0 adds the last five: a tamper-evident audit chain, secret references resolved into a page-locked vault, kernel events to callbacks, process-wide access to the foundation, and the OS random source checked at boot. Windows services now stop, reload, and dump through the service control manager.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse. Each part is its own published library behind its own feature.

```rust
// hive.conf:  [database]  password = "file:/run/secrets/db_password"
fn main() -> std::process::ExitCode {
    let system = match system_suite::start!() {
        Ok(system) => system,
        Err(error) => return error.report(),
    };
    // The bytes are only visible inside `with`, in a buffer wiped afterwards.
    let _password = system.config().secret("database.password");
    system.run()
}
```

## What's in 0.5.0

- **Secrets, never in the file:** `env:NAME`, `file:/path`, and `vault:name` references are resolved at boot into key-vault's page-locked, wiped-on-drop storage, and read only inside `Secret::with`. A plain password under a key named like a secret is refused. A secret file another user can read is refused. A reload resolves again without changing what the configuration in force reads.
- **An audit chain you can trust:** `system.audit().record(actor, action, target, outcome)` appends a hash-linked record, on disk before it returns. At every boot the whole chain is verified before anything new is written; a changed, removed, or reordered record stops the boot. A record cut short by a crash is set aside only when you allow it, and its bytes are kept. The kernel records reloads, lockdowns, and stops itself.
- **Kernel events:** register a callback for phase changes, urgent-line changes, reloads and refusals, worker restarts and failures, and subsystem stops. A panicking callback is isolated and logged.
- **`system_suite::foundation()`:** the running system's handles, for code that cannot be handed them.
- **Randomness:** the OS random source is checked at boot, so a sandbox that blocks it is named at once.
- **Windows services:** `run()` hands the main thread to the service control manager; `sc stop` stops, `sc control <name> paramchange` reloads, `sc control <name> 128` dumps.
- **Documentation:** architecture, every configuration key, and platform notes.

Getting here took two member releases, made in the members themselves: audit-trail 1.1.0 (verified open and resume, owner-only files, sync, a clock that never goes back) and signal-mod 2.1.0 (Windows service control, tested against a real service in CI).
