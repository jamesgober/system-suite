# system-suite v0.9.1 - Members' review releases

**The members' fixes from their independent reviews, adopted.** path-lib 1.3, signal-mod 2.2.1, log-io 2.2, metrics-lib 2.2, config-lib 1.4, and registry-io 1.2. No API change; a version bump is all most services need.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Signals

- **signal-mod 2.2.1 is required.** With signal-mod 2.2.0, which 0.9.0 also accepts, a service that stopped quickly on SIGTERM could be killed by that same SIGTERM partway through its shutdown (about 1 stop in 15 on a loaded Linux machine), losing the last log lines and the steps after it. A 0.9.0 build gets the fix with `cargo update -p signal-mod`.
- The stop set is signal-mod's `SignalSet::stop()`: SIGTERM and SIGINT, and Ctrl+Break on Windows.
- **SIGQUIT is no longer caught.** It quits with a core dump, as the OS intends, which is what an operator sends a hung process for. SIGTERM is the graceful stop.
- A stop signal the process inherited as ignored stays ignored: SIGHUP under `nohup`, SIGINT for a job a script started in the background.
- Windows: a logoff never reaches the kernel (signal-mod declines it), and a machine shutdown stops the process gracefully.

## Behaviour from the members

- **Directories:** every directory the application uses that already exists is checked for owner and permissions (path-lib 1.3), and is never changed. One that another account owns or can change, or can read for the log, data, and runtime directories, stops the boot with the new `ErrorKind::DirectoryInsecure` (exit code 77) and a message saying what to fix. A `logs` directory made by hand at `0755` needs `chmod 700`, or deleting so the suite creates it.
- **Logging:** a log file that is a symbolic link is refused, and new log files are `0600` on Unix.
- **Configuration (CONF):** `password = abc#def` keeps `abc#def` (a `#` starts a comment only at the start of a value or after whitespace), text after a value on its line is refused, and parse errors never quote the input.
- **Metrics:** one family holds at most 5000 series by default. `[metrics] max_family_series` (new) raises or lowers it.
- **Registry:** handler ids are unique across registries, and removing a handler from inside a handler on two threads at once no longer deadlocks.
