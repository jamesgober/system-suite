# system-suite v0.8.1 - Second pre-1.0 pass

**An independent security review of the whole suite, every finding fixed or recorded with its reason.** v0.8.1 closes ten findings, one of them high, adopts config-lib 1.3's strict parsing, and profiles boot and stop step by step on Windows. No API changes.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## Security fixes

- **TOML and NOML `include` and `env()` (high).** A `.toml` or `.noml` configuration could pull in another file (`include "path"`, read with no owner, mode, size, or regular-file check, relative to the working directory) or copy any environment variable into a value (`env("NAME")`). config-lib 1.3 refuses both in TOML, and the suite now parses NOML strictly, so every value comes from the one file that passed the checks.
- **Secrets inside lists.** A plain password in a list's table (`[[pools]]`) was accepted, and a reference there was read back as its literal text. Lists are walked to any depth.
- **A key spelled twice.** `{"db": {"password": ...}, "db.password": ...}` gave a lookup and the secret table different answers; it is refused. A dotted top-level key for a suite section (`kernel.notify = false`), which was silently ignored, is refused with the section to use.
- **Panics.** A configuration parser that panics refuses the file (config-lib 1.3 also fixes the `conf` panic on non-ASCII text and its quadratic parse time). A subsystem whose `health` panics is `Unhealthy`, at boot too. One panicking reload or dump no longer stops every later reload and dump signal.
- **Files.** A `file:` secret, the audit chain, and its anchor must be regular files, checked before opening; the anchor is read only to 4 KiB.
- **Audit records.** Each field is cut to 4 KiB, so request text cannot make one record megabytes long. A record appended but not synced says so, so a caller does not write it twice.
- **Timers.** A cancelled timer kept its closure until its due time, up to 30 days; cancelled timers are swept when the table doubles.
- **A slow audit disk at shutdown.** With `[audit] sync = "every"`, the stop's own record was synced at the first shutdown step against the whole deadline. On a slow disk that spent the subsystems' time and they were abandoned without a chance to stop. The record is now written through to the OS there and synced with every other record at step 5, and the first step is bounded by the subsystems' share.

Two limits are recorded instead of fixed, with their reasons in `docs/SECURITY.md`: a FIFO swapped in between a file's check and its open, and a shutdown step run without its deadline when the OS refuses a thread.

## Faster

- A stop no longer starts a thread to wait for a reload when none is running: about 450 µs to 300 µs on Windows. The full Windows profile is in `docs/PERFORMANCE.md`.

## Behaviour changes

Each of these refuses a file that loaded in 0.8.0:
- a TOML or NOML file with `include` or a function call;
- a file that spells one key twice;
- a dotted top-level key for a suite section;
- a plain value under a secret-looking key inside a list.

The setting was either not being read, or the file was getting around a stated defence. The error names the key and what to write instead.

## Members

- config-lib 1.3.0: strict TOML and NOML, byte positions and linear time in `conf`, INI, and Properties, bracket lists of unquoted items.
- sys-lib 0.5.0: additive over 0.4; nothing new in the tree.
