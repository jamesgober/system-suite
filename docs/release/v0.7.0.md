# system-suite v0.7.0 - Hardening

**Every threat has a passing attack test.** v0.7.0 closes a security review of the whole suite, anchors the audit chain so a cut or replaced chain is refused, hands the configuration out read-only, and publishes `docs/SECURITY.md`: each threat, its defence, what the defence costs, and the test that attacks it.

## What is system-suite?

<strong>system-suite</strong> is the foundation for Rust services: one dependency that brings system facts and a process guard, application paths, environment variables, configuration, logging, metrics, audit records, a registry, signal handling, time, ids, randomness, and secret storage, plus a kernel that starts them in order, supervises background work, reports health and readiness, captures crashes, and shuts everything down in reverse.

## What's in 0.7.0

- **An audit anchor:** the chain's last id and hash are kept outside the chain file and checked at boot, so records cut from the end are noticed (`AuditTampered`).
- **A read-only configuration snapshot:** `config_snapshot()` returns a `SnapshotView`; only a validated reload replaces the configuration.
- **A sturdier signal path:** a panicking handler no longer ends the intake, and reloads and dumps run off the signal thread.
- **Reloads that cannot half-happen:** a stop during a reload cancels it, a panicking commit is caught, and a bad shutdown deadline is refused.
- **Tighter file checks:** the `.env` file is checked on the file actually read; FIFOs and devices are refused before they are opened; an audit chain another user can change is refused.
- **Secrets:** a reference inside a list, or under a disabled secrets member, is refused; nothing resolved after the shutdown wipe survives it.
- **New attack tests:** T3 for the audit chain and anchor, T5 for a panicking worker, T8 with a real SIGTERM during boot.
- **Soak:** 8 hours on Linux (WSL 2), 251,225 start, reload, and stop cycles: heap 21,830 bytes, 4 descriptors, and 2 threads at the start and at the end (the worst moment mid-cycle: 23,440 bytes and 4 threads, both back down).

## Breaking change

`config_snapshot()` now returns `&SnapshotView<Config>`. `.reader()`, `.load()`, and `.version()` work as before; `.publish()` is gone from it on purpose.
